# 审批流程需求交付表

## 填写说明

每个审批应用单独填写一份。可直接复制本表到对话、文档或表格中填写；对话填写时按[逐项问答辅助](intake-assistance.md)一次回答一题。字段、接口、版本和能力证据应来自业务系统、字段字典、正式接口文档、发布清单或配置后台。未知信息不要猜测，填写“待确认”，并补充确认人和截止时间。本表不要求也不输出节点设计表、流程图或实际节点配置。完成后请在[在线登记表](https://www.kdocs.cn/l/co5Ah0IILUqN)中登记。

## 1 业务表单接入问卷

| 信息项 | 必填性 | 为什么需要 | 如何提供 | 填写内容 |
| --- | --- | --- | --- | --- |
| 所属业务线 | 必填 | 确定审批应用归属和责任人 | 填写系统中的业务线名称或标识，以及负责人 |  |
| 关联业务单据 | 必填 | 具体业务表单是创建审批流程的前置条件，用于关联审批对象、表单数据和审计记录 | 仅填写具体表单名称（如“新建权证”）；若尚无业务单据，先定义业务单据，不能创建审批流程 |  |
| 触发审批按钮 | 必填 | 明确用户操作与创建审批的发起时机 | 仅填写业务表单上实际触发审批的按钮名称 |  |
| 适用范围 | 必填 | 业务表单的对应字段会与适用范围匹配，以定位唯一、明确的流程模型 | 选择资产、权限组、部门、班级、点位或无需区分；其中资产和权限组可以同时选择，其他选项单选。不填写取值或范围。业务表单必须包含并能匹配所选适用范围的字段；后续由配置人员在系统中配置流程模型时会校验适用范围值不重复，同一个值不能出现在不同流程模型中；选择“无需区分”时，该表单在系统中只能创建一个流程模型 |  |
| 摘要格式 | 必填 | 明确待办中展示的摘要内容 | 文本不加括号，字段使用【字段名】进行组合；所选字段必须存在于该表单 |  |
| 特殊条件字段 | 必填 | 确认后续配置可能依赖哪些表单字段 | 填写“无”，或填写字段名称（【字段名】）；不收集条件规则，所选字段必须存在于该表单 |  |
| 可确认字段 | 必填 | 明确审批过程能否修改业务单据及其控制要求 | 填写“不允许修改”，或填写可修改字段、适用参与人、校验规则和修改后的处理要求 |  |
| 审批详情页展示字段 | 必填 | 明确审批人员在审批详情页可查看的业务信息 | 填写业务表单字段名称（【字段名】、【字段名】）；所选字段必须存在于该表单 |  |
| Web 审批详情跳转 | 必填 | 确认流程引擎的审批页跳转目标 | 填写是否跳转；若是，填写业务详情页名称或路由标识。流程引擎仅负责跳转，目标页内如需查看相关审批，由业务方自行实现页面和逻辑 |  |
| APP 审批与页面跳转 | 必填 | 明确 APP 端支持范围与展示要求 | 填写是否支持、审批页展示字段、是否跳转及目标 APP 页面；不支持填写“不支持” |  |
| H5 审批与详情跳转 | 必填 | 明确 H5 端支持范围与展示要求 | 填写是否支持、审批页展示字段、是否跳转及目标详情页；不支持填写“不支持” |  |

> 研发注意：新增业务表单审批时，在所属业务线的“业务校验”中补充该表单。业务校验是控制业务单据是否必须审批的流程关联开关；无需在本表定义开关值。

## 2 补充信息

| 信息项 | 必填性 | 为什么需要 | 如何提供 | 填写内容 |
| --- | --- | --- | --- | --- |
| 字段字典 | 必填 | 保证展示、权限、路由和审计使用同一数据定义 | 每个字段填写标识、名称、类型、值域/单位、来源、取值时点、必填性和敏感级别 |  |
| 标题与摘要 | 必填 | 让待办可识别 | 标题按业务需要填写；摘要由文本和业务表单字段组合，文本不加括号、字段使用【字段名】，所选字段必须存在于该表单 |  |
| 分支字段 | 有分支时必填 | 记录后续配置可能使用的业务表单字段 | 仅填写字段名称（【字段名】）；不收集条件规则 |  |
| 多人处理与参与人依据 | 有人工处理时必填 | 避免无人、多人或组织变化造成业务中断 | 描述按用户、角色、组织关系或业务规则的解析依据及无人/多人/离职兜底 |  |
| 业务操作规则 | 必填 | 明确业务对提交、同意、退回等结果的期望 | 说明允许的操作、操作者、业务前置条件、结果和不需要的禁用操作 |  |

只记录业务规则；不得在本表中写节点名称、节点顺序、连线、节点参数或流程图。

## 3 权限、异常与数据要求

| 信息项 | 必填性 | 为什么需要 | 如何提供 | 填写内容 |
| --- | --- | --- | --- | --- |
| 字段与操作权限 | 必填 | 落实最小权限并保护敏感数据 | 按发起人、审批参与人、管理员等角色填写可见、只读、可编辑和可执行范围 |  |
| 快照与实时数据 | 必填 | 保证在途审批可还原且数据变化可解释 | 为每个关键字段选择发起快照或实时读取，并说明原因 |  |
| 异常与恢复 | 必填 | 防止重复、超时、无人或失败导致业务卡死 | 填写参与人为空、重复发起、超时、通知失败、回调失败和业务执行失败的处理原则 |  |
| 通知、审计与保留 | 必填 | 支持追溯、运维和合规检查 | 填写通知对象/渠道、需记录的审计信息、查询方式和保留要求 |  |

## 4 集成与能力依据

| 信息项 | 必填性 | 为什么需要 | 如何提供 | 填写内容 |
| --- | --- | --- | --- | --- |
| 发起与查询 | 必填 | 定义业务系统如何创建和查询审批实例 | 提供业务唯一标识、发起时机、调用系统和正式接口文档链接或编号 |  |
| 事件或回调 | 有结果联动时必填 | 防止重复消费并支持对账与补偿 | 填写消费方、事件类型、幂等键、重试、超时、对账和补偿责任人 |  |
| 鉴权与隔离 | 必填 | 防止越权和跨组织数据访问 | 填写身份来源、租户/组织边界、签名验签和日志脱敏要求 |  |
| 能力证据与归属 | 必填 | 避免把原型或设想当成已上线能力 | 对每项能力引用发布清单、正式接口、配置后台或验收记录；标记功能应用、通用候选或业务侧实现 |  |

## 5 待确认、验收与责任

| 信息项 | 必填性 | 为什么需要 | 如何提供 | 填写内容 |
| --- | --- | --- | --- | --- |
| 待确认项 | 有缺口时必填 | 防止未决问题进入开发或上线 | 写影响、确认人、截止时间和是否阻塞 |  |
| 验收标准 | 必填 | 验证需求被正确实现 | 按“给定条件、执行动作、预期结果”编写，覆盖权限、重复、异常、版本和恢复 |  |
| 风险与上线条件 | 必填 | 确保责任和补救措施明确 | 写风险、建议、决策人、上线前置条件、回滚和补偿安排 |  |

## 6 原型交付材料

- 必须在原型中贴上在线登记表截图和《审批流程需求交付表》。
- 可选补充触发审批按钮和跳转目标页面的截图，用于说明操作入口与页面联动。
